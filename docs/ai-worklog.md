## 0. Входные данные (17.10, до старта)

- Бриф: `kvarta-brief.pdf` + страница ТЗ `tz.vitai.world`. Сверил построчно: PDF и сайт совпадают;
  ключевые дополнительные требования, которых не было в пересказе: живая ссылка, коммиты по шагам,
  лог работы с ИИ, замер Lighthouse Mobile, README на полстраницы.
- **Мои решения до кода:** стек Next.js App Router + TypeScript + Tailwind + lucide-react;
  без корзины/оплаты (по брифу); дизайн — бумага/сериф/терракота, никаких градиентов и glassmorphism;
  хранение заявок — не файл; главный заголовок — «Кофе, который ещё помнит четверг» (из трёх вариантов).
- Окружение: Windows, Node 24, pnpm 11, Docker, Edge/Chrome for Testing; GitHub — push в конце.

## 1. Дизайн-система и ассеты

- Палитра: `#F6F1E7` бумага, `#1E1B18` кофейный текст, `#B4502A` жжёная терракота, `#C68A3C` охра.
- Типографика: Literata (заголовки) + Golos Text (текст) + Caveat (рукописные акценты).
  Шрифты скачаны и **сабсетнуты локально** (кириллица+латиница, инстансинг осей): суммарно ~128 КБ woff2.
- Фото: подобраны вручную с Unsplash (ростер, пуровер, руки основателей, мешок зерна, пачка+кофемолка),
  кадрированы и сжаты в WebP; OG-превью 1200×630 и иконки собраны на Python (Pillow).
- Первый сгенерированный hero **отклонён**: градиент + стеклянные карточки + «инновационная обжарка» →
  см. `docs/ai-drafts/template-hero.tsx`. Пересобрали первый экран на бумаге и серифах.

## 2. Лендинг

- Секции: hero с расписанием обжарки, бегущая строка, манифест свежести, история Ани и Дмитрия,
  каталог с фильтром по обжарке, подписка, доставка/самовывоз, FAQ, форма, подвал.
- Даты обжарки считаются на сервере (`getRoastSchedule`, Europe/Minsk): четверг — обжарка,
  пятница — развозка, дедлайн заказов — среда 20:00. ISR раз в час, чтобы даты не устаревали.
- Тексты переписаны от лица Ани и Дмитрия, с конкретикой (5 кг, 1–3 день, ул. Короля, 9).

## 3. Форма заявки

- Маска телефона: `+375 (29) 123-45-67`, поддержка мобильных (25/29/33/44) и городских (код с 1),
  ввод `80…`/`0…`/`375…`, backspace по разделителям, вставка из буфера.
- Валидация одна и та же на клиенте и сервере (`src/lib/lead-schema.ts`), ошибки — человеческим языком.
- UTM: `utm_source/medium/campaign/content/term`, `yclid/gclid/fbclid`, `document.referrer`, текущая страница;
  first-touch в `sessionStorage`, метки читаются в момент отправки; тело запроса проверено в QA.
- Состояния: отправка (кнопка блокируется), успех, «заявка уже была» (дубль), ошибка с телефоном и Telegram.
- Пресеты из каталога/подписки: «Заказать» подставляет сорт в комментарий и таб «Заказ зерна».

## 4. API, дедуп и Telegram

- `POST /api/lead`: rate limit → JSON/размер → валидация → honeypot → дедуп 10 минут → Telegram → лог.
- **Ошибка ИИ:** первым делом сгенерировал SQLite-хранилище (`docs/ai-drafts/sqlite-store.ts`).
  Поймал на этапе архитектуры: на Vercel ФС read-only/ephemeral, данные и дедуп развалятся.
- Итог: Telegram Bot API как надёжная доставка + история в чате; дедуп — память инстанса,
  при заданном Upstash — атомарный `SET NX EX` (строго между инстансами); локально `.data/leads.jsonl`.
- При сбое Telegram слот дедупликации освобождается, чтобы человек мог повторить отправку.
- Уведомление форматированное (HTML, экранирование), с UTM, страницей, referrer и ID заявки.

## 5. Производительность и Lighthouse — самая итеративная часть

| Итерация | Что сделал | Результат |
| --- | --- | --- |
| 1 | базовая сборка, next/image, локальные шрифты | Perf 69, TBT 1000 мс |
| 2 | **убрал SVG-шум (feTurbulence) — ошибка ИИ**, TBT обвалился | Perf 89, TBT 170 мс |
| 3 | добавил `content-visibility: auto` ниже первого экрана | Perf 92, TBT 110 мс |
| 4 | **инлайн CSS — ошибка ИИ**, TBT вырос | Perf 70 → откатил |
| 5 | убрал `text-wrap: pretty/balance` с каждого абзаца | Perf 92, TBT ~110 мс |
| 6 | шрифты: инстансинг + сабсет, 211 КБ → 45 КБ Literata | LCP/вес лучше |
| 7 | `content-visibility` на все секции ниже первого экрана + перенос рукописного шрифта из hero | **финал: Perf 95 · A11y 100 · BP 100 · SEO 100**, FCP 1.1 s, LCP 2.6 s, TBT 170 ms, CLS 0 |

Финальный отчёт — `docs/screenshots/lighthouse-mobile.html`, цифры — `lighthouse-scores.txt`,
картинка-сводка — `lighthouse-scores.png`. Важно: на локальном железе замер сильно гуляет
(тот же билд даёт от 77 до 95), поэтому в «что улучшил бы» вынес стабилизацию замера в CI.

## 6. Тесты и QA

- 65 тестов: маска/валидация телефона, расписание (включая переход года), UTM/first-touch,
  схема заявки, rate limit, дедуп-хранилище, формат Telegram и HTML-экранирование, API-роут
  (успех, дубль, сбой Telegram с повтором, honeypot, флуд, битый JSON, javascript:-referrer).
- **Реальные баги, поймавшиеся тестами:** маска принимала лишние цифры (10-значный номер) — исправлено;
  тест на 31 декабря вскрыл путаницу «сегодня/следующая неделя» — логика подтверждена тестом.
- Playwright QA (`scripts/qa-screenshots.mjs`): маска, UTM в теле запроса, дубль, клиентская валидация,
  экран ошибки, пресет каталога, отсутствие горизонтального оверфлоу — отчёт в `docs/screenshots/qa-report.txt`.
